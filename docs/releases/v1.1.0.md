# v1.1.0 · 喷泉码持续修复与 Windows 接收端

这个版本增加可选的喷泉码实验模式，减少单向屏幕传输中等待缺帧重播的时间。
原有固定 FEC 仍是默认模式。

## 新增能力

- 首轮以原始帧为主，周期性穿插 XOR 修复帧；首轮结束后持续生成新的修复帧。
- 提供 32:1、32:2、16:1、8:1 四种原始帧与修复帧比例，喷泉码默认使用 32:2。
- 接收端自动识别 v2 帧，恢复的分片沿用原有落盘与断点续传流程。
- 增加通俗原理说明、引入决策记录、四种比例的仿真及真实桌面对照报告。

喷泉码可以理解为：除了发送文件碎片，还不断发送碎片之间的新关系。
接收端用收到的关系算出缺失内容，减少等待某个指定原始帧再次出现的时间。
当前实现为每组最多 32 个分片的系统式 XOR 随机线性编码，不是标准 LT/RaptorQ。

## 实测收益与取舍

同一份 1 MiB 文件、30 FPS、每种配置三次真实桌面对照：

| 抓屏后端 | 固定 FEC 中位耗时 | 喷泉码 32:2 中位耗时 | 变化 |
|---|---:|---:|---|
| MSS | 33.216 秒 | 21.239 秒 | 耗时缩短 36.1%，约 1.56 倍吞吐 |
| DXGI | 15.980 秒 | 16.921 秒 | 耗时增加 5.9% |

收益主要来自丢帧后的补齐，无丢帧时修复帧会占用发送时隙，所以不保证所有链路提速。
15 次有效实测全部通过 SHA-256 校验；600 次固定种子仿真覆盖四种比例及五类丢帧条件。
发布前全量回归为 403 项通过。

## 下载与升级

- `receiver_gui.exe`：重新打包的 Windows 接收端，包含喷泉码 v2 模块。
- `sender.html`：新版浏览器发送页，直接用现代浏览器打开。
- `tapemaker_gui.exe`：制作端，本次未修改，复用 v1.0.0 产物；仍输出原有协议的视频。
- `SHA256SUMS.txt`：以上三个文件的 SHA-256 校验值。

启用喷泉码请配套更新发送页和接收端：v1.0.0 接收端不支持 v2。
页面选择“喷泉码（实验 v2）”后，等接收端确认还原再停止播放。
同一文件切换纠错模式时，应清空其旧的未完成任务进度。
已恢复分片可续传，未解出的修复方程仅保存在内存，重启后重新累计。
PNG 导出是有限修复序列，不能保证任意损失都能恢复。
