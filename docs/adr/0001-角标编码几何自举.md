# 0001 - 采用角标编码法实现接收端几何自举

日期：2026-09-21 · 状态：已接受

## 背景

需求确定"接收端无默认几何参数，一切从画面自行解析"。这产生自举悖论：要读帧头里的几何参数（COLS/ROWS/BIT/PAD），必须先按几何参数采样网格；而采样前几何参数未知。

## 决策

角标尺寸与 BIT 建立严格比例关系：**角标白色实心方块边长 ≡ 3×BIT 像素**，贴数据网格四角外沿。接收端先检测角标（四条几何一致性约束），测白块边长 ÷ 3 得 BIT，由四角标定画布尺寸得 COLS/ROWS，再读帧头交叉校验，不一致整帧丢弃。

## 备选方案

1. **网格自检测**（被否）：沿扫描线找黑白跳变间距估计方块尺寸。实现复杂，摩尔纹与压缩伪影下跳变间距不可靠。
2. **引导帧**（被否）：第一帧固定用一套全局已知几何发送参数。两端仍各藏一套常量，违背"无默认参数"的需求；且引导帧几何本身无法校验。

## 后果

- 正面：全程无默认值、确定性推导、一次测量即锁定全部几何；帧头交叉校验提供第二道防线。
- 负面：角标比例成为协议冻结项，角标尺寸今后不可独立变更；角标测量精度直接决定 BIT 推导，测量误差 ±1 像素在 BIT 很小时影响放大，calibrate 需覆盖该场景。

## 追记（2026-09-22，issue #20）

显示缩放 ≠100% 时接收端（mss 抓屏）测得的是物理像素，冻结校验隐含「1 位图 px = 1 物理 px」的前提。本 ADR 的测量模型不变，但明确口径：**BIT 一律按物理像素声明与测量**。发送端把 CSS 输入经 `devicePixelRatio` 换算为物理值（四舍五入保持整数 BIT），画布位图与 CSS 显示尺寸按 dpr 反算保证 1:1；播放时画布锚定画面左上角，保证网格原点恒为 PAD×BIT（「画面即画布」，接收端 `pad = x0 // bit` 的前提）。物理 BIT 受帧头 4 bit 上限（≤15）约束，超限组合需另立协议版本。

## 追记（2026-09-22，issue #22）：推翻「画面即画布」假设

区域框选要求「框大一点」——采集矩形与画布之间允许任意边距，与「画面即画布」假设冲突。核实几何关系后确认：**角标锚定的是数据网格矩形**（角标内角 = 数据网格外角），COLS/ROWS/BIT 的测量与 PAD 无关；PAD 只决定画布外沿静默边，而静默边在裁切采集下不可见，**PAD 在几何上不可测**。据此：

- 退役原点对齐校验（`x0 % BIT == 0`、`pad == y0 // bit`）与 PAD 的几何交叉校验；
- PAD 以帧头声明为准，完整性由 CRC（覆盖帧头）保证——CRC 本就使几何交叉校验对帧头损坏冗余，退役不引入新风险；
- 接收端由此容忍任意裁切边距，网格定位不依赖画面边缘；上一追记的「锚定左上角保证原点恒为 PAD×BIT」约束同步失效（不再必要）；
- calibrate 的探针残差改以角标边长折算（栅格原点残差不可用），PNG 精确流 δ 恒为 0，推荐即实测值；δ 通道保留给降质源（camera）探针。

线缆协议零改动；代价是 ±1px 整体平移从「整帧拒绝」变为「合法裁切偏移、照常解码」，画面受损由 CRC 兜底。
