# 0002 - 采用分组前向纠错降低单向信道尾部缺帧

日期：2026-09-25 · 状态：已接受

## 背景

屏幕信道严格单向，接收端不能像 HTTP Range 或迅雷那样请求某个缺失分片。
当前发送端无限重播全部数据帧，接收端按帧号乱序落盘；少数帧持续识别失败时，
即使进度已经接近 100%，gzip 仍不能安全还原，传输会长期停在尾部。

## 决策

采用固定分组的系统式 FEC：每 32 个数据帧发送 2 个校验帧。校验帧分别是
组内数据的逐字节 XOR，以及带 GF(256) 递增系数的线性校验。接收端收到校验
帧后，可恢复同组最多 2 个缺失数据帧；恢复结果按原帧号写入既有位图和定长
数据文件。FEC 帧使用 `FLAGS.bit14` 标识，数据帧和 `TOTAL_FRAMES` 语义保持
兼容，协议版本字段仍为 1。

## 备选方案

1. **只打乱帧顺序**：不能减少缺帧，也不能恢复缺失字节，放弃。
2. **选择性重传**：需要反向通道，违反严格单向约束，放弃。
3. **完整 Reed-Solomon / Fountain Code**：恢复能力更强，但实现和帧头协商
   复杂度更高；当前先用固定 2 缺帧能力覆盖实际尾部问题，后续可扩展分组参数。

## 后果

- 正面：接收不要求连续；每组少量缺帧可在本地恢复，减少等待整轮重播。
- 正面：旧的无 FEC 数据帧仍可读取，FEC 是帧头 flags 的兼容扩展。
- 负面：每 32 帧增加 2 帧（约 6.25%）传输量；同组缺失超过 2 帧时仍需重播。
- 负面：校验帧依赖固定 `CHUNK_SIZE`，末帧必须零填充并在还原时按元数据截断。
