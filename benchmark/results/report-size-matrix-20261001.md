## 测试条件

- 现有 benchmark/run_bench_live.py，有头 Chromium 真实窗口播放与 DXGI 真实桌面采集，生产 run_receive 核心。
- 发送 30 FPS、CSS BIT=6、PAD=3；物理 BIT=8，216×91 网格，每数据帧 2,431 字节。
- 窗口 1536×816 DIP，DPR=1.25，采集区域 1920×976 物理像素。
- 每个样本正式统计一次；采集器先就绪，每个测试使用独立进度目录，无旧进度。
- 六次均无队列丢帧；逐帧日志确认全部数据帧直接接收，重复数据帧为零，没有依赖重播或 FEC 恢复缺失数据。
- 最初三次对准自检采到其他窗口，未进入接收测试，不计入结果；窗口可见后重跑通过。另一次日志试跑因控制台 GBK 输出异常未纳入正式六次结果。

## 样本与复现

生成器固定随机种子 20261001。二进制是伪随机字节，用于模拟已压缩内容的低压缩率，不能视为实际 JPG、ZIP 或 MP4 样本。日志包含变化的请求 ID、耗时和用户编号；CSV 包含变化的编号、类别、金额、数量和引用编号。日志与 CSV 均为 UTF-8 合成数据，其压缩率不代表所有真实业务文件。

样本、生成与测试脚本、清单及汇总位于 retest-size-matrix/（已被仓库 retest*/ 规则忽略）。原始基准 JSON/CSV 位于本报告同目录，前缀 live_desktop_results_dxgi_size-matrix-20261001-。逐帧日志位于 benchmark/results/work/size-matrix-20261001-*/traces/。

```powershell
.venv/Scripts/python.exe retest-size-matrix/run_matrix.py
.venv/Scripts/python.exe retest-size-matrix/summarize.py
```

## 对 README 的建议

本机实测：难压缩内容 1 MB 约 15 秒，5 MB 约 80 秒，10 MB 约 161 秒；因此 1–5 MB 适合日常摆渡，10 MB 应预留约 3 分钟。可压缩文本可明显更快：本次 10 MB 模拟日志约 28 秒，5 MB 模拟 CSV 约 31 秒。

这不是所有机器、采集后端和文件类型的速度保证。每档仅一次正式测试，适合作为样本实测展示，不用于推断成功率或耗时分布。camera、远程桌面和视频二次压缩未包含在本轮测试中。README 本轮未修改。
